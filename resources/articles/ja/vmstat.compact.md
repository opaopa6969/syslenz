# メモリ圧縮 (Compaction) — vmstat

[English version](../en/vmstat.compact.md)

---

## これは何？

**メモリ圧縮（Compaction）**はカーネルが物理メモリをデフラグする仕組みです。時間とともに空きページが小さな島状に散らばります。圧縮はページを移動して連続した大きな空き領域を作ります。主にTransparent Huge Page (THP)の割り当てリクエストを満たすために使われます。

```
圧縮前:                   圧縮後:
[使用][空き][使用][空き]   [使用][使用][空き][空き]
[空き][使用][空き][使用]   [使用][使用][空き][空き]
         ↕                         ↕
  2MBブロック確保不可       連続した2MBブロック確保可能！
```

2つのアクターが圧縮を実行します：
- **ダイレクト圧縮**：プロセスが大きなページを今すぐ必要とする場合に発動 — 同期的、プロセスをストール
- **kcompactd**：バックグラウンドデーモン、積極的にメモリをデフラグ

---

## メトリクス早見表

| メトリクス | カウントするもの |
|-----------|----------------|
| `compact_stall` | ダイレクト圧縮ストール（プロセスブロック） |
| `compact_fail` | 大きなブロックが見つからなかった圧縮試行 |
| `compact_success` | 大きなブロックを解放できた圧縮試行 |
| `compact_migrate_scanned` | 移動するページを探してスキャンしたページ数 |
| `compact_daemon_wake` | kcompactdの起動回数 |

---

## なぜ重要？

**`compact_stall`が主要シグナル。** ストールのたびにプロセスがブロックされます。レイテンシ敏感なアプリ（DB、Webサーバー）では原因不明のレイテンシスパイクとして現れます。

THP割り当てによるストールが問題なら、THPを`madvise`モードに設定してください — 明示的にTHPを要求するアプリだけが対象となり、バックグラウンド圧縮プレッシャーがなくなります。
