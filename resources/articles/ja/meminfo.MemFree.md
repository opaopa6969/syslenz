# MemFree

[English version](../en/meminfo.MemFree.md)

---

## これは何？

`MemFree` は、何にも使われていないRAMの量です——アプリにも、カーネルにも、ファイルキャッシュにも。カーネルが完全にアイドルと判断しているメモリです。

健全で忙しいLinuxサーバーでは、`MemFree` はほぼ常に低い値です。これは意図的な設計です。

```
  Windows / macOS の感覚：
  ┌──────────────────────────────────┐
  │ 使用中  ████████████  8 GB        │
  │ 空き    ░░░░░░░░░░░░  8 GB ← 良い │
  └──────────────────────────────────┘

  Linuxの現実：
  ┌──────────────────────────────────┐
  │ アプリ  ████  4 GB               │
  │ キャッシュ ████████████ 11 GB ← 良い │
  │ 空き    ░  1 GB      ← これも正常 │
  └──────────────────────────────────┘
```

Linuxはアイドルなメモリを積極的にファイルキャッシュとして使います。カーネルの哲学は：**空きメモリは無駄なメモリ**。ページが何か有用なものをキャッシュしていないなら、次のディスク読み取りを高速化する機会を逃しています。

---

## なぜ重要？

ほとんどの場合、重要ではありません——そこがポイントです。

`MemFree` が意味を持つのはいくつかの特定の状況に限られます：

**本物のメモリ枯渇。** `MemFree` と `MemAvailable` が同時にゼロに近ければ、システムはメモリ不足です。ただしこれは最終手段のシグナルです——`MemAvailable` は `MemFree` がゼロになるずっと前に警告を出します。

**`drop_caches` 後。** ページキャッシュを強制的に追い出すと `MemFree` が急上昇します。これはキャッシュが空きメモリに戻っただけで、すぐにまた消費されます。

**スワップなし・キャッシュが極小のシステム。** 512 MB RAMでスワップなしのコンテナでは、小さな `MemFree` が本当に圧力を示すことがあります。

大多数のケースでは、`MemFree` を見て心配しているなら、**代わりに `MemAvailable` を見るべきです。**

## 読み方

```sh
# MemFree だけ見てはいけない。こう読む：
grep -E "MemTotal|MemFree|MemAvailable|Cached" /proc/meminfo

# または free(1) を使う — "available" 列が重要
free -h
```

ルール：`MemAvailable` が健全（MemTotalの20%以上）なら、低い `MemFree` は完全に正常です。

## 実際のエピソード

新人エンジニアが、忙しいPostgreSQLサーバーを運用している会社に入社しました。最初の仕事はヘルスチェックです。`free -m` を実行すると 64 GB マシンで `MemFree: 247 MB` と表示されました。彼は緊急インシデントを起票しました：「サーバーのメモリが危機的に不足しています」

オンコールのDBAがそれを見て指摘しました：`MemAvailable` は 42 GB——システムには42 GBの余裕があったのです。「消えた」メモリは、ディスクを触らずにクエリを返せるよう、58 GBのPostgreSQLのワーキングセットがページキャッシュに乗っていただけでした。

新人エンジニアはLinuxメモリ監視で最も多い間違いを犯していました：「free（空き）」と「available（利用可能）」を混同することです。彼はその後メンタルモデルを修正して良いシステムエンジニアになりましたが、そのとき1時間、全員がデータベースがクラッシュすると思っていました。

教訓：監視ツールをインストールする前に、Linuxのメモリモデルをインストールしよう。

## よくある間違い

**`MemFree` を健全性指標として使う。** そうではありません。`MemAvailable` を使ってください。

**「MemFreeを直すため」にキャッシュを解放する。** `echo 3 > /proc/sys/vm/drop_caches` で `MemFree` は跳ね上がりますが、パフォーマンスに貢献していたキャッシュを破壊します。何も直していません——システムを遅くしただけです。

**低いMemFreeにアラートを設定する。** 健全なシステムで常に誤報が出ます。代わりに `MemAvailable` のパーセンテージでアラートを設定してください。

**`MemFree` を未使用容量と混同する。** キャッシュも容量です——ただ「使用中」に見えるだけです。アプリケーションがメモリを必要とすると、カーネルはミリ秒でキャッシュページを回収します。

## 関連項目

- `meminfo.MemAvailable` — 実際に監視すべき指標
- `meminfo.Cached` — 「使用中」に見えるメモリのほとんどを占めるファイルキャッシュ
- `meminfo.AnonPages` — 本物のアプリメモリ（回収不可能）
