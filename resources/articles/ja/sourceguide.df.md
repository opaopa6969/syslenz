# ソースガイド: df

## NAME
`sourceguide.df` - source単位の運用読解ガイド

## なぜ今読むか
単一sourceを読みつつ、他source文脈を失いたくない時に読みます。
単独sourceが有力に見える時ほど、単独で証明できない範囲を検証します。

## 証拠の順序
1. 先にユーザー症状と時刻窓を固定する。
2. この記事の主シグナルのトレンドを確認する。
3. 隣接シグナル1つと跨層シグナル1つで照合する。
4. 可逆な緩和策を当て、回復トレンドを検証する。

## SEE ALSO
記事オーバーレイの関連記事リンクから、同じ証拠連鎖を辿ってください。

## この source の役割
`df` はプロトコル層のテレメトリ面です。ソケット挙動、パケットの進行、ユーザー体感遅延を接続して読むために使います。

## 運用エピソード
CPU・メモリは健全でも、この source のプロトコルカウンタが再試行や状態遷移異常を示し、断続タイムアウトの説明になったケースがありました。

## 読み方
1. 安定しやすい基線カウンタから始める。
2. 負荷スパイク時に先行して動くカウンタを特定する。
3. `ss` / conntrack / pressure とトレンドを照合する。
4. カウンタ変動を接続ライフサイクル段階に対応づける。

## パターン集
- 健全: トラフィック比例で増え、収束も速い。
- 警戒: トラフィック増加と独立に特定エラー/再試行が伸びる。
- 重大: 複数エラーパスが同時上昇し、正常進行が停滞する。

## 推奨ワークフロー
1. 最初の異常時刻を刻む。
2. ソケット層1つ・圧力層1つを必ずクロスチェックする。
3. 緩和策（レート制御、タイムアウト調整、リトライ方針）を選ぶ。
4. 再発時に使える証拠連鎖を残す。

## Unix内部システム視点

この field は **Unixカーネル実行副作用の発露** です。

- process / syscall / scheduler / memory / I/O / interrupt の層で捉える。
- この field がどの層の副作用かを先に固定する。
- 隣接 field 1つと跨層 field 1つで検証する。

## システム叙述（ストレージ）

このシグナル（sourceguide.df）は単なる数字ではなく、カーネル状態遷移の露出面です。
この source は跨層の証拠連鎖に組み込むと信頼性が大きく上がります。

### エピソード: ダッシュボードの安心感とユーザー痛みがずれた日（ストレージ）
- ストレージ平均値は正常で、ダッシュボードは緑でした。
- しかしユーザー遅延はストレージバースト窓だけで悪化しました。
- このストレージ field が先に動き、隣接 field が方向を裏付けました。
- 勝ち筋は大きなストレージ調整ではなく、不確実性を素早く狭めることでした。

### 跨層翻訳（ストレージ）
1. field の動きを、起こり得るカーネル経路に翻訳する。
2. 壁時計時間の損失が scheduler 遅延か I/O wait かを検証する。
3. 需要増とサービス時間増を分離する。
4. 変更後に症状と機序の両方で回復を確認する。

### シニアレビューでよく問われる点（ストレージ）
- 時系列で最初に動いたストレージカウンタは何か？
- 有力に見えたが副作用へ降格したストレージカウンタは何か？
- ユーザー影響を運んだストレージ系実行経路は何か？
- 可逆なストレージ対策と、ロールバックトリガは定義されたか？

### Unix内部との接続（ストレージ）
- process model（ストレージ視点）: runnable が増えたのか、blocked が滞留したのか。
- syscall lifecycle（ストレージ視点）: request時間は entry/sleep/wakeup/return のどこへ移ったか。
- interrupt path（ストレージ視点）: wakeup配送や softirq backlog が tail を押し上げたか。
- scheduler（ストレージ視点）: fairness は throughput を守りつつ tail を悪化させていないか。

## インシデント演習（ストレージ）

### 演習A: 先行シグナル特定（ストレージ）
1. 1つの障害窓を選び、関連3シグナルの先行順を注記する。

### 演習B: 可逆対策の設計（ストレージ）
1. 5分以内でロールバック可能な対策を1つ定義する。
2. 適用前にロールバック条件を明文化する。
3. 変更後は症状と機序を分離して追跡する。

### 演習C: 証拠圧縮（ストレージ）
1. 症状、先行シグナル、補助シグナル、行動、反応、結論を6行で書く。
2. 形容表現を削り、検証可能な文だけ残す。
3. 別のエンジニアに渡し、推論が再現できるか確認する。
