# pgmajfault

[English version](../en/vmstat.pgmajfault.md)

---

## これは何？

`pgmajfault` は**メジャーページフォルト**の数を計上します。プロセスが仮想メモリのアドレスにアクセスしようとした時、必要なページが**RAMにない**場合に発生するイベントです。カーネルはプロセスを続行させる前に、ディスク（スワップ領域またはファイル）からページを読み込まなければなりません。

メジャーフォルトはマイナーフォルトと根本的に異なります。マイナーフォルトはマイクロ秒（ページテーブルの更新だけ）。メジャーフォルトはミリ秒 — ディスク読み込みが完了するまでプロセスをブロックします。

```
  マイナーフォルト（高速）：
  プロセス → アドレス未マップ → ページがRAMにある → マップする → 続行
                                                       ~1 µs

  メジャーフォルト（低速）：
  プロセス → アドレス未マップ → ページがRAMにない → ディスクから読み込む
                                                      → マップする → 続行
                                                      ~5〜50 ms（HDD）
                                                      ~0.1〜1 ms（SSD）
```

本番サーバーでメジャーフォルトが最も多く発生する原因：
1. **スワップ読み込み** — メモリ圧力でページアウトされ、今読み戻されている
2. **コールドファイル読み込み** — 最近アクセスされていないファイル、ページキャッシュにない
3. **OOM後** — OOMキルで生き残ったプロセスのページが退去された後

---

## なぜ重要？

ごく少数のメジャーフォルトでも目に見えるレイテンシスパイクを引き起こす可能性があります。突然ページ読み込みに10ms以上かかるようになったリクエスト処理プロセスは、アプリケーションが遅いように見えて、実はメモリの問題です。

**典型的な誤読：** 「アプリケーションが遅い」が、本当の原因は「アプリのメモリが昨夜スワップアウトされ、今すべてのアクセスがディスク読み込みになっている」。

現実の影響：HDDシステムで毎秒100件のメジャーフォルトは、ページ読み込みだけで毎秒最低500msのブロッキングを意味します。プロセス間で不均等に分散されるため、レイテンシがスパイク状になり診断しにくくなります。

```
  メジャーフォルトがレイテンシに与える影響：

  通常のリクエスト：[ アプリロジック 2ms ]
  メジャーフォルト中：[ ページ待ち 30ms ][ アプリロジック 2ms ]

  外から見ると：「なぜこのリクエストが時々15倍遅いのか？」
```

## 読み方

```sh
# システム全体のレート（vmstat出力の11番目のカラム）
vmstat 1 5
# ヘッダー：r b swpd free buff cache si so bi bo in cs us sy id wa st
# si（スワップイン）とbi（ブロックイン）もページがスワップ/ディスクから来ているか示す

# プロセスごとのレート
pidstat -f 1 5
# majflt/s カラムを見る

# プロセスの履歴カウント
cat /proc/<PID>/stat | awk '{print "minor:", $10, "major:", $12}'
```

| `pgmajfault` レート（毎秒） | 解釈 |
|---------------------------|------|
| 0〜2/秒 | 正常なバックグラウンド活動 |
| 2〜20/秒 | 散発的。`vmstat si` で監視 |
| 20〜100/秒 | 顕著なレイテンシ影響。メモリを調査 |
| 100/秒超 | 深刻。スラッシングまたは大量コールド読み込み |

**スワップとの相関：**
```sh
# スワップが読まれているか？（si = スワップインページ数/秒）
vmstat 1 | awk '{print "swap_in:", $7, "major_faults:", $11}'
```

`vmstat si`（スワップイン）が高く `pgmajfault` も高い → スワップから読み込んでいる。これはほぼ必ず最優先で修正すべき問題です。

## 実際のエピソード

あるECサイトのJavaアプリケーションが朝のトラフィックは問題なく処理するが、08:00以降の最初の10〜15分は一貫して遅かった。エンジニアたちは「JVMのウォームアップ」と決めつけて数ヶ月間放置していた。

新しいエンジニアが08:05に `pgmajfault` を見た：
```sh
pidstat -f 1 | grep java
# PID  minflt/s  majflt/s
# 2381   8,200    1,847
```

毎秒1,847件のメジャーフォルト。JVMは全力でスワップからページを読み込んでいた。

調査結果：夜間のOOMイベントが低優先度のバックグラウンドプロセスを静かに強制終了し、04:00頃にJVMのヒープページを部分的にスワップアウトさせていた。朝になるとヒープはスワップの中にあった。JVMの最初の15分のトラフィックはほぼディスク読み込みだった。

適用した修正：
1. OOM圧力を下げるためスワップメモリを追加
2. ヒープページがスワップされないよう `mlockall()` JVMオプションを追加
3. 根本原因の修正：バックグラウンドプロセスのメモリリークを修正

修正後、朝のメジャーフォルトは0.3/秒。「JVMのウォームアップ」のレイテンシは完全に消えた。

**教訓：** 閑散期（夜間、週末）の後にアプリケーションが一貫して遅い場合、`pgmajfault` を確認すること。「ウォームアップ」は多くの場合ただの「メモリがスワップアウトされていた」だ。

## 高い時にやること

**ステップ1：スワップが関係しているか確認する。**
```sh
vmstat 1 5
# si（7番目のカラム）= 毎秒スワップから読まれるページ数
# siが0より大きく上昇中なら、スワップスラッシングの問題だ
```

**ステップ2：スワップ使用量を確認する。**
```sh
free -h
swapon -s
cat /proc/swaps
```

**ステップ3：どのプロセスがフォルトを引き起こしているか特定する。**
```sh
pidstat -f 1 5
# majflt/s でソートして犯人を探す
```

**ステップ4：根本原因に対処する。**

```sh
# オプションA：プロセスがメモリを使いすぎ → リークを発見して修正
# RSS（常駐セットサイズ）のトレンドを確認
ps -o pid,rss,vsz,comm -p <PID>

# オプションB：OOMがページを退去させている → スワップ追加またはメモリ圧力削減
vmstat 1 | grep -E "^[0-9]" | awk '{print "free:", $4, "swap_used:", $3}'

# オプションC：重要プロセスのページをRAMにロック
# （アプリケーションコード内で）
# mlockall(MCL_CURRENT | MCL_FUTURE)  # スワッピングを防ぐ

# オプションD：OOM退去を避けるためプロセスを優先する
echo -100 > /proc/<PID>/oom_score_adj
```

**ステップ5：ファイルベースのメジャーフォルト（コールド読み込み、スワップではない）の場合：**
- ページキャッシュを拡大するためRAMを増やす
- 起動時にキャッシュを意図的にウォームアップする
- `posix_fadvise(FADV_WILLNEED)` でアプリが必要とするファイルをプリフェッチ

## よくある間違い

**「JVMのウォームアップ」や「アプリ起動の問題」と決めつける。** 閑散期の後5〜20分間Java/Python/Rubyアプリが遅い場合、ランタイムの問題と決めつける前に `pgmajfault` を確認すること。多くの場合スワップだ。

**`pgmajfault = 0` を見てメモリ圧力なしと思い込む。** ページキャッシュから読み込まれる場合（スワップではないがコールド）、ページを持ち込む必要がある時だけメジャーフォルトとして現れる。キャッシュがウォームになるとメジャーフォルトは下がる。起動後に `pgmajfault` が0に下がっても、起動中に問題がなかったことを意味しない。

**スワップかコールド読み込みかを理解せずにメジャーフォルトを修正しようとする。** これらは異なる解決策が必要だ。スワップ：メモリ圧力を削減するかスワップを追加。コールド読み込み：キャッシュをウォームアップするかRAMを追加。

**OOMの履歴を確認しない。** スワップからのメジャーフォルトを見たら、`dmesg` や `journalctl` でOOMキルイベントを確認すること。遅くなっているプロセスは、強制終了されたプロセスとは別のことが多い。

## 関連項目

- `vmstat.pgfault` — 安価なマイナーフォルトを含む全ページフォルト
- `vmstat.pswpin` — ディスクからスワップインされたページ。スワップ読み込みの直接指標
- `vmstat.pswpout` — スワップアウトされたページ。高い場合スワップ圧力が高まっている
- `pressure/memory_some_avg10` — PSIメモリ圧力。タスクがストールしているか確認
- `stat.cpu_iowait` — pgmajfaultと合わせて高い場合、ディスクがボトルネック
