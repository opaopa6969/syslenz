## 概要

syslenz は監視ツールであると同時に、教育ツールでもあります。組み込みの教育システムは、主要サブシステムごとにストーリー仕立ての解説、診断フローチャート、よくある問題パターンを提供し、Linux の内部構造の学習を支援します。自分のシステムのライブデータと合わせて見ることで、抽象的なカーネルの概念が具体的に理解できます。

## ヘルプレベル

`?` を押して4つのヘルプレベルを切り替えます:

| レベル | ラベル | 表示内容 |
|--------|--------|---------|
| OFF | `OFF` | ヘルプパネルなし |
| NORMAL | `NORMAL` | 基本的なキーバインドと現在のビューの説明 |
| DETAILED | `DETAILED` | 選択ソースのフィールド説明、単位、読み方のヒント |
| EXTRA | `EXTRA` | カーネルの背景知識、関連ファイル、他ソースへの相互参照を含む拡張説明 |

ヘルプパネルは画面下部に表示され、`j`/`k` でスクロールできます。高速スクロールには `PageUp`/`PageDown` を使ってください。

## カテゴリガイド

`C` を押すとカテゴリガイドビューが開きます。サブシステム別に整理された詳しい教育コンテンツです:

| カテゴリ | アイコン | 関連ソース |
|---------|--------|----------|
| **メモリ** | MEM | meminfo, vmstat, swaps, buddyinfo, pressure, zoneinfo, slabinfo, pagetypeinfo |
| **CPU / 負荷** | CPU | stat, loadavg, cpuinfo, pressure, schedstat, softirqs, interrupts |
| **ネットワーク** | NET | net/dev, net/tcp, net/udp, net/unix, net/arp, net/route, net/sockstat, net/snmp, net/netstat, net/wireless, dns, conntrack, ip_route, ip_neighbor, ss_summary |
| **ストレージ** | DSK | diskstats, df, mounts, partitions, pressure, locks |
| **プロセス** | PRC | processes, file-nr, stat |

### ナビゲーション

| キー | アクション |
|------|----------|
| `h` / `l` または 矢印キー左右 | カテゴリを切り替え |
| `j` / `k` または 矢印キー上下 | コンテンツをスクロール |
| `PageUp` / `PageDown` | ページ単位でスクロール |
| `Backspace` | 前のビューに戻る |

各カテゴリページには4つのセクションがあります:
1. **概要** -- サブシステムの役割と重要性
2. **ストーリー** -- ナラティブ形式のウォークスルー（「RAMはどこに消えた？」）
3. **診断フロー** -- トラブルシューティングのステップバイステップ判断木
4. **よくある問題** -- よく遭遇する問題とその解決策

## メモリのストーリー

**「RAMはどこに消えた？」**

メモリガイドは、Linux で最も誤解されがちなメモリ管理を解説します。

**主なポイント:**
- 健全なLinuxシステムでは、カーネルがディスクデータを積極的にキャッシュするため、ほぼ全てのRAMが「使用中」に見える
- 「使用中」は「利用不可」ではない -- `MemAvailable`（`MemFree` ではない）が真の指標
- `MemAvailable` が低下するとカーネルはスワップを開始
- `vmstat` の `si`（スワップイン）と `so`（スワップアウト）でアクティブなスワップを確認
- PSI `memory_some_avg10 > 0` はタスクが実際にメモリ待ちで停滞していることを意味
- `buddyinfo` で各割り当てオーダーのメモリ断片化を確認

**診断フロー:**
1. `meminfo` → `MemAvailable` を確認。`MemTotal` の10%以上なら問題なし
2. `Cached + Buffers` を確認。大きければキャッシュがRAMを使用中（正常）
3. `swaps` → `SwapUsed` を確認。増加中ならアクティブにスワップ中
4. `vmstat` → `si`、`so`、`pgmajfault` を確認。非ゼロならスワップスラッシング
5. `pressure` → `memory_some_avg10` を確認。> 0 ならタスクが停滞中

**よくある問題:** OOM Killer、「RAMがいっぱい！」の誤認、メモリリーク（増加するRSS）、スワップストーム、スラブキャッシュの肥大化。

## CPUのストーリー

**「なぜサーバーが遅いのか？」**

CPUガイドは、ロードアベレージ、CPU使用率の内訳、プレッシャーストール情報を説明します。

**主なポイント:**
- ロードアベレージは需要（実行キュー + I/O待ち）を測定するもので、使用率ではない
- ロード < コア数ならCPUは過負荷でない
- `stat` がCPU時間の内訳を表示: user、system、idle、iowait、steal
- `iowait` が高いとCPUがビジーに見えるが、実際はCPUが低速ストレージを待っている
- PSI `cpu_some_avg10` はCPU競合の最も直接的な指標
- `schedstat` でCPUごとのスケジューリング統計を確認
- `stat` の `context_switches` が高い場合、スレッド間の競合が多すぎる可能性

**診断フロー:**
1. `loadavg` → `load1` を CPU数と比較。ロード < コア数ならCPUはボトルネックでない
2. `stat` → `cpu_iowait`（高い = I/O問題）、`cpu_user`（高い = アプリがCPUバウンド）、`cpu_system`（高い = カーネルオーバーヘッド）を確認
3. `pressure` → `cpu_some_avg10` を確認。> 0 ならタスクがCPU待ちで停滞
4. `stat` → `context_switches` で過度なスレッド競合を確認

## ネットワークのストーリー

**「なぜ接続が失敗するのか？」**

ネットワークガイドは、TCP接続状態、ソケット統計、インターフェーストラフィックをカバーします。

**主なポイント:**
- TCP接続状態はアプリの挙動を明らかにする: `ESTABLISHED`（アクティブ）、`TIME_WAIT`（最近閉じた）、`CLOSE_WAIT`（FDリーク）、`SYN_SENT`（接続先到達不可）
- `net/sockstat` でソケットメモリ使用量と割り当て数を確認
- `net/snmp` にプロトコルレベルのエラーカウンター（再送、順序外セグメント）がある
- `net/dev` にインターフェースごとのエラーとドロップカウンター付きトラフィックが表示
- 非ゼロのドロップはバッファオーバーフローまたはレート制限を示す

**よくある問題:** ソケットFDリーク（増加するCLOSE_WAIT）、エフェメラルポート枯渇（多数のTIME_WAIT）、接続タイムアウト（SYN_SENT）、再送ストーム。

## ストレージのストーリー

**「なぜディスクが遅いのか？」**

ストレージガイドは、ディスクI/O、ファイルシステム使用率、マウントオプションをカバーします。

**主なポイント:**
- `diskstats` でデバイスごとのI/O操作、転送バイト数、消費時間を確認
- `df` でファイルシステム使用率を確認
- `mounts` で全マウントファイルシステムとオプションを一覧表示
- PSI `io_some_avg10` でI/O待ちによるタスク停滞を測定
- `locks` でプロセスが保持しているファイルロックを確認

**よくある問題:** ディスク満杯（ログ、テンポラリファイル）、I/Oボトルネック（遅いHDD）、マウントオプションの問題（noatime、sync）。

## プロセスのストーリー

**「これらのプロセスは何をしているのか？」**

プロセスガイドは、プロセス状態、リソース消費、ファイルディスクリプタ管理をカバーします。

**主なポイント:**
- プロセス状態: R（実行中）、S（スリープ）、D（割り込み不可I/O）、Z（ゾンビ）、T（停止）
- RSS（Resident Set Size）は実際に使われている物理メモリ量
- ゾンビプロセスは親が `wait()` を呼んでいないことを示す
- D状態プロセスはI/Oで行き詰まっており、killできない
- `file-nr` でシステム全体のファイルディスクリプタ使用量を追跡

## 学習パス

### パス1: 「Linux管理が初めてです」

1. **ダッシュボード**から始めて、システムの状態をひと目で理解
2. **カテゴリガイド**（`C`）を開き、まずメモリのストーリーを読む
3. クラシックモード（`O`）に切り替え、`meminfo` を選択し、読んだ内容とライブデータを比較
4. ヘルプを有効化（`?` を2回押してDETAILEDレベル）してフィールドの説明を確認
5. ガイドの診断フローをライブシステムで試す

### パス2: 「パフォーマンス問題をデバッグしたい」

1. **自動診断**（`X`）を開いて自動検出結果を確認
2. 重要度を確認し、CRIT項目から着手
3. 該当サブシステムの**カテゴリガイド**を開く
4. 診断フローをステップバイステップでたどる
5. クラシックモードでガイドに記載のソースを検査

### パス3: 「Linux内部を深く理解したい」

1. 5つのカテゴリガイド全て（メモリ、CPU、ネットワーク、ストレージ、プロセス）を読む
2. ヘルプをEXTRAレベルにして最大限の詳細を表示
3. クラシックモードで各ソースを検査し、全フィールドの説明を読む
4. 差分ビュー（`d`）でカウンターの時間変化を観察
5. グラフビュー（`g`）でトレンドを可視化
6. 健全なシステムとストレス下のシステムを比較（保存したスナップショットを `--import` で使用）
